# HOTA_NEW_HERO_V1.12：固定幸运 +3 与首次攻击必定幸运

日期：2026-07-26
状态：正式发布；用户实机验收、独立验证、可复现构建、运行时钩子与标准/HD 启动门禁通过

## 发布内容

1. 壁垒马洛迪亚（英雄 ID `29`）与塔楼黛瑞丝（英雄 ID `43`）继续保留原正式版效果：英雄所率领部队的幸运值始终为 `+3`。
2. 两位英雄所率领的每支部队，在每场战斗中首次主动攻击时必定触发幸运；之后按常驻 `+3` 幸运的原生概率判定。
3. 首次资格以阵营和战斗队列索引逐队记录，战斗初始化时全部重置。
4. 只有主动近战和主动射击会消耗资格；反击、等待、防御和施法不会消耗。
5. 双射、环击等同一主动攻击指令内的全部命中共享该次必定幸运。
6. 厄运沙漏、诅咒之地及同类“直接禁止幸运生效”的原生硬封锁仍然优先于固定 `+3` 和首次必定幸运。
7. 游戏内中文特长描述更新为：“英雄所率领部队的幸运值始终为+3，且每支部队在每场战斗中首次主动攻击时必定触发幸运。”
8. 马洛迪亚的初级智慧术 + 初级神秘术、黛瑞丝的初级智慧术 + 初级智力以及两人魔法书初始自带振奋全部保持不变。

## TEST1 失败与 TEST2 修复

- TEST1 的行动入口、逐队资格、英雄门禁和攻守方指针匹配均正确，但在物理攻击回调中写入 `isLucky=1` 的时机过早；HotA 的真实幸运函数随后覆盖该值，因此用户测试的近战、反击、射击、双射和环击均未生效。
- 回传 `hota_luck_firsttest01.bin` 共 18 条完整记录，证明首次主动攻击的 `force=1` 与回调 `isLucky: 0 -> 1` 均出现，从而把故障准确限定为写入时序。
- TEST2 将钩子移动到 HotA 实际幸运函数首选 VA `0x10133880`，符合首次条件时进入原生成功分支；用户确认所有测试项目均已实现，同意发布小版本。
- 正式 V1.12 删除 TEST2 的二进制诊断文件写入，只保留已验收的功能路径。
