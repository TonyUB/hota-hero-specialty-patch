# HOTA_NEW_HERO_V1.04_LOG_TEST2：群体日志、兵种等级与中文描述修正

状态：**双 EXE 静态门禁、可复现构建、中文资源回滚及临时副本启动冒烟已通过；战斗内群体日志和数值仍待用户实机验收，尚未提升为正式 V1.04。**

## TEST1 实机结果

- 单体治愈日志正确，顺序为“治愈施放提示 → 兵种治愈值 → 原版复活提示”。
- 群体治愈与群体复活稳定，治愈提示和原版复活提示的相对顺序正确，但没有显示各兵种治愈值。
- `L=1、P=1`、无额外数值加成时，对1级泉水精灵显示 `+60`，而 F6 Direct 的设计锚点应为 `+40`。
- 游戏内治愈特长说明仍显示 HotA 1.8.0 原始文字。

## 三个根因

1. **兵种等级被倒置。** H3API 的 `H3CombatCreature` 显示 `+0x74` 是战斗内复制的 `H3CreatureInformation`，其中 `+0x78` 的 `level` 为 `0–6`。V1.03 错误地使用 `7 - [stack+0x78]`，令1级兵的字段0变成公式等级7，因此初始值从40变为60。
2. **群体尸体绕过 TEST1 包装器。** 群体尸体扫描在 `0x00639C98` 直接调用总量计算器；TEST1 只修改了 `0x00639EA5` 的单体全灭尸体入口。同时，`0x00639C29` 的群体尸体扫描初始化发生在活体循环之后，TEST1 在这里清空治疗缓存，导致已记录的群体活体数值也丢失。
3. **HD 中文 loose 文件覆盖 LOD。** 两个补丁 LOD 内的 `HeroSpec.txt` 已是简化描述，但 `_HD3_Data/Packs/H3中文-基础资源/HeroSpec.txt` 具有更高运行时优先级，仍保留“使用疗伤魔法时效果大增……”的原始说明。

## TEST2 修正

- F6 数学公式保持不变；实现改为 `n = clamp(*(int32*)(stack+0x78) + 1, 1, 7)`。因此 `L=1、P=1、n=1、w=0/1` 返回40，`n=7` 返回60。
- `0x00639C98` 与 `0x00639EA5` 两个全灭尸体计算入口均接入同一日志包装器。
- 群体尸体扫描入口只清除原版复活消息计数，不再清除已经由群体活体循环积累的治疗值；治疗值仍在原版治愈提示追加后统一刷新，然后才回放原版复活提示。
- 新增 `_HD3_Data/Packs/H3中文-基础资源/HeroSpec.txt` 覆盖文件，仅把治愈行替换为：`治愈术的效果随英雄等级和目标生物等级提升，并可永久复活己方阵亡单位。`
