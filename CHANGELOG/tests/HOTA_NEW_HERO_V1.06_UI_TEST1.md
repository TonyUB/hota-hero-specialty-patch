# HOTA_NEW_HERO_V1.06_UI_TEST1：治愈悬停精确值与魔法书动态范围

状态：**已撤回，禁止继续使用。实机证明魔法书和悬停均未进入这两个 EXE 候选入口；更严重的是魔法书载荷覆盖了运行时治疗日志状态区，尸体复活在 `0x0065DC42` 崩溃。测试 ZIP、构建器和验证器已经删除，只保留本经验日志。请重新覆盖正式 V1.05。**

## 问题与根因

- 正式 V1.05 的实际治疗/复活总量、逐队战斗日志和英雄特长详情表已经使用 F7 NativePower 公式。
- 战斗中把治愈术指向目标时，底部仍显示原版预览值 `10 + 5P`；初始力量 `P=1` 因此显示15。
- 魔法书说明构造器也继续调用原版通用法术效果计算器，并且传入空目标，所以无法取得 F7 公式所需的目标生物等级 `n`。
- 截图中的目标是三级兵海贼；在 `L=1、P=1、w=1` 时，F7 精确值是46。40仅对应一级兵，七级兵对应60。

## 测试版设计

1. **目标悬停：** 在标准版与 HD 版的 `0x005A7C26`，只把原通用效果调用改接到专属分发器。分发器仅识别英雄 ID 25/170、治愈术 ID 37及非空目标；读取目标 `+0x78` 的零基兵种等级后，调用正式 V1.05 已验收的 `0x0065DF00` F7 界面计算器。其他英雄、其他魔法和空目标尾跳原生 `0x004E59D0`。
2. **魔法书范围：** 在 `0x0059C017`，把原本地化 `sprintf` 调用改接到范围格式器。它只对两名治愈特英雄计算 `n=1` 与 `n=7` 两端值，并把运行时语言格式串中的第一个 `%d` 安全扩展为 `%d-%d`。因此中文、英文及原有括号/前后缀不被硬编码覆盖。
3. **群体语义：** 高级水系群体治愈仍逐队按各自等级结算；魔法书只显示当前英雄的1—7级范围，不虚构一个群体公共值。
4. **保持原版：** 普通英雄仍显示原版治愈值；实际治疗、复活、日志、特长详情、动画、音效、目标资格和资源文件全部继承 V1.05。

## 实机失败结果与崩溃根因

- 魔法书仍显示原版数值，证明 `0x0059C017` 不是 HD 中文界面实际可见的最终格式化链，或结果随后被 HD/HotA 的第二层缓存重建。
- 战斗悬停仍显示原版数值，证明 `0x005A7C26` 不是当前 HD 悬停文字的最终显示链，不能以静态通用效果调用直接推定可见入口。
- 对尸体使用治愈复活时立即崩溃。报告记录：
  - 模块：`h3hota HD.exe`；
  - 异常地址：`0x0065DC42`；
  - 类型：读取地址 `0x0F04C85C` 的访问冲突；
  - 调用链：`0x0065DC30` 治疗日志追加助手 → `0x0065DCC2` → `0x005A8C60` → `0x005A1B03`。
- `0x0065DC42` 位于正式 V1.05 的治疗记录追加逻辑。TEST1 覆盖 `0x0065DD7C/0x0065DD80` 后，计数与记录指针被当作机器码/残留值读取，最终形成无效地址；这与崩溃寄存器和调用栈完全吻合。
- 本次启动冒烟未进入战斗，因此无法暴露只在治疗日志缓存启用后出现的状态区破坏。以后所有零区分配必须把运行时状态地址作为显式禁区，而不能只验证文件静态零态与外侧边界。

## 经验与风险

- 不能把原生 `SPTRAITS.TXT` 治愈基础值直接改为40，否则普通英雄也会被全局增强。
- 悬停调用本身具有目标指针，可以显示精确值；魔法书调用明确传入空目标，只能显示范围或约定的参考等级。
- 魔法书格式必须在运行时扩展原本地化格式，不能硬编码中文，否则会破坏英文资源和原有标点。
- **静态零区不等于代码洞。** 必须把所有既有运行时计数、数组、缓存、指针和相邻调用者交叉列入禁区图，再判断可分配范围。
- **EXE 通用计算入口不等于 HD 可见界面入口。** 下一步必须先用只写独立诊断文件的 Hook 记录真实调用者，并同时观察 `HD_HOTA.dll`/`HotA.dll` 的二次格式化链，不能继续盲改显示结果。
- 静态与启动门禁不能代替战斗界面实测；正式 V1.06 必须等待诊断和后续界面测试全部通过。
