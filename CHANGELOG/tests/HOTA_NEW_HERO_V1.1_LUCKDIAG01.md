# HOTA_NEW_HERO_V1.1_LUCKDIAG01：幸运原生封锁路径诊断

日期：2026-07-25
状态：运行日志已回传并完成解码；普通幸运运行路径已证实，厄运沙漏分支留给功能测试包核验

## 目的

为马洛迪亚（英雄 ID `29`）与黛瑞丝（英雄 ID `43`）后续“所率部队幸运值始终为 +3”特长寻找最小且不绕过原生封锁的挂点。本轮只记录路径，不修改幸运返回值、英雄初始配置或资源文本。

## 已确认的原生路径

- `H3Hero::GetLuckBonus`：`0x004E3930`。
- 诅咒之地参数检查：`0x004E394B`—`0x004E3959`。
- 己方厄运沙漏（宝物 ID `0x55`）扫描：`0x004E3964`。
- 敌方厄运沙漏扫描：`0x004E39A9`。
- 原生封锁返回 0：`0x004E39DE`—`0x004E39E5`。
- 通过封锁后进入普通幸运数值计算：`0x004E39E8`。

因此正式实现的候选边界为 `0x004E39E8`：只在原生封锁检查全部通过之后，对英雄 ID 29/43 返回 `3`。厄运沙漏、诅咒之地及同类“禁止幸运生效”条件仍先返回 `0`。

## 诊断 Hook

标准版与 HD 版原始字节完全相同，并安装相同诊断负载。

- VA：`0x004E3930`

- 诊断：`e9 4b 38 20 00 90 90 90`
- 目标：`0x006E7180`

### 原生封锁之后

- VA：`0x004E39E8`

两个包装器均回放被覆盖指令并返回原生继续地址，不更改函数返回值。诊断代码放在独立新节 `.luckdg`：RVA `0x002E7000`、VA `0x006E7000`、大小 `0x1000`、属性 `0xE0000020`。

## 记录格式

- 文件：`hota_luck_diag01.bin`
- 每条：40 字节（10 个小端 DWORD）
- 魔数：`LCK1`
- 字段：stage、调用者返回地址、英雄指针、英雄 ID、敌方英雄指针、诅咒之地参数、钳制参数、英雄 `+0x105` 标志、保留值。
- 解码器：`tools/decode_hota_luck_diag01.py`

预期结果：

- 普通战斗：同一次读取出现 `stage 1`，随后出现 `stage 2`；
- 厄运沙漏生效：出现 `stage 1`，但不出现对应的 `stage 2`。

结论：马洛迪亚普通战斗的运行路径已证实，可以在 `0x004E39E8` 进行最小功能 Hook；不把 Hook 前移到原生硬封锁之前。
