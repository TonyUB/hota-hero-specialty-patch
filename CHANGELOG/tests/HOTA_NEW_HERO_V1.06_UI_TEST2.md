## 修复目标

UIDIAG04 已经锁定最终可见入口：

1. 活体悬停在 `HotA.dll` 的 `0x1006DA00–0x1006DA0F` 使用原版法术基础值与旧特长奖励，最终在 `0x1006DA49` 格式化为 `%s` 字符串；
2. 魔法书 Cure 分支 `0x1013D8AB–0x1013D8D5` 计算原版整数15，并在 `0x1013DA03` 使用本地化 `%d` 格式；
3. 尸体没有进入上述两条治疗点数链路。

本轮不再修改未命中的 EXE 候选入口，也不占用任何既有静态零区或战斗状态区。

## 实现

- 从正式 `HOTA_NEW_HERO_V1.05` 重新构建；
- 两个 EXE、DAT、LOD、HeroSpec、战斗日志及其他资源逐字节继承正式版；
- 仅修改 `HotA.dll` 和根目录安装说明；
- 在原 `HotA.dll` 映像边界 `RVA 0x04692000` 新增独立 `.cureui` 节；
- DLL 内部的 Hook、辅助函数、返回路径和原生格式化调用全部使用相对控制转移，保持 ASLR 安全；
- 外部计算只调用两个固定基址 EXE 中已经存在并经过 V1.05 构建门禁的 F7 计算器，不复制第二套数学公式。

### 活体悬停

`0x1006DA00` 原16字节逻辑：

```text
push 原版基础值
push 目标等级字段
push 法术ID
call 0x004E6260
add esi,eax
```

改为调用 `.cureui` 分发器：

- 只有英雄 ID 25/170 且法术 ID 37 时，读取实际目标兵队和当前英雄状态，计算水系附加值后调用正式 `0x0065DE40` F7 总量计算器；
- 其他英雄和法术复刻原16字节的原生奖励逻辑；
- 返回值直接成为 HotA 后续 `%s` 格式化所使用的最终预览量。

因此初始 `L=1、P=1、w=1` 时，1级、3级、7级目标应分别显示40、46、60。

### 魔法书

只改 Cure 分支末尾 `0x1013D8D1` 的既有五字节跳转：

- 普通英雄原样跳回原生共用出口，继续显示15；
- 尤兰德/阿斯特拉通过正式 `0x0065DF00` F7 UI 计算器分别取得 `n=1` 与 `n=7` 的当前值；
- 运行时复制当前语言的原始格式，并仅把第一个 `%d` 扩展为 `%d-%d`；
- 中文初始显示“治疗 40-60 点的生命值。”；英文与其他语言保留各自原句和标点；
- 若本地化格式意外没有 `%d`，安全退化为单个1级参考值，不传递不匹配的可变参数。
