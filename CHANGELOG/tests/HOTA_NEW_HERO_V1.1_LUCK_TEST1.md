# HOTA_NEW_HERO_V1.1_LUCK_TEST1：幸运特长功能测试

日期：2026-07-25
状态：用户确认游戏内功能已经生效；静态验证、独立验证、可复现构建和隔离启动门禁通过，已按相同游戏文件晋升正式 V1.1

## 本轮目标

将壁垒幸运特马洛迪亚（英雄 ID `29`）和塔楼幸运特黛瑞丝（英雄 ID `43`）改为固定幸运特长：

- 普通情况下，两人所率部队的最终幸运值固定为 `+3`；
- 普通正负幸运数值，包括事件、敌方兵种和宝物的数值影响，不能改变这一结果；
- 厄运沙漏、诅咒之地及同类“直接禁止幸运生效”的原生硬封锁仍然有效；
- 不建立额外状态，不修改全局幸运之神魔法，也不影响其他英雄。

同时修改英雄初始配置：

- 马洛迪亚：初级智慧术 + 初级神秘术，魔法书初始法术为振奋；
- 黛瑞丝：初级智慧术 + 初级智力保持不变，魔法书初始法术改为振奋；
- 两人的特长详细说明改为“英雄所率领部队的幸运值始终为+3。”

## 运行路径与实现

诊断包 `HOTA_NEW_HERO_V1.1_LUCKDIAG01` 的用户回传日志包含 `720` 条完整记录：`stage 1/2` 各 `360` 条且全部配对，证明马洛迪亚的实际幸运读取抵达原生硬封锁之后的 `0x004E39E8`。

功能 Hook：

- VA：`0x004E39E8`
- 文件偏移：`0x000E39E8`
- 原始/回滚：`8a 86 d2 00 00 00`
- 测试版：`e9 13 36 20 00 90`
- 目标：`0x006E7000`
- 新节：`.luck3`，RVA `0x002E7000`，大小 `0x1000`，属性 `0xE0000020`

包装器只在英雄 ID 为 `29/43` 时直接完成函数收尾并返回 `3`；其他英雄回放被覆盖的 `mov al, [esi+0xd2]` 后返回原生 `0x004E39EE`。

原生封锁先于 Hook：

- 己方厄运沙漏扫描：`0x004E3964`
- 敌方厄运沙漏扫描：`0x004E39A9`
- 原生封锁返回 0：`0x004E39DE`—`0x004E39E5`

因此厄运沙漏命中时不会抵达功能 Hook，也不会被固定 `+3` 绕过。界面在这种硬封锁下可能沿用原生逻辑显示 `0`。
