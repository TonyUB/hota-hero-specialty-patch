# HOTA_NEW_HERO_V1.13 启动测试记录

日期：2026-07-26

## 测试目标

- 验证标准版 `h3hota.exe` 与高清启动器 `h3hota HD.exe` 均能正常启动。
- 验证幸运特长的运行时跳板、固定幸运 +3 和首次攻击必定幸运的钩子仍然完整。
- 确认测试结束后游戏目录恢复到测试前状态。

## 测试过程与诊断

1. 首次选择 `C:\Game\180\180` 测试时，检测到用户正在该目录运行游戏。测试在写入前安全中止，没有终止进程，也没有修改目录内容。
2. 改用干净备份 `D:\BaiduNetdiskDownload\HOMM3 HotA1.80\180` 后，首次运行仍被诊断脚本拦截。原因是旧脚本会把其他游戏目录中正在运行的 `h3hota` 进程也视为冲突，而不是只检查本次测试目录。
3. 将启动与运行时诊断脚本的进程检查范围限制为指定 `GameRoot` 后重新测试。上一次尝试复制的文件已在 `finally` 阶段按原始哈希完整恢复。

## 最终结果

- 标准版启动测试：通过，持续运行 8 秒，无崩溃。
- HD 版启动测试：通过，持续运行 8 秒，无崩溃。
- 运行时跳板验证：
  - `0x004E39E8 -> 0x006E7000`
  - `0x00463B71 -> 0x006E7500`
  - `0x00478D70 -> 0x006E7580`
  - `0x00478B94 -> 0x006E7600`
- 固定幸运 +3、HotA 实际幸运判定入口与首次攻击必定幸运逻辑：全部通过。
- 两次最终测试结束后，目标目录内所有文件均恢复为测试前哈希。

## 经验总结

- 同一台机器可能同时存在多套 HotA 测试目录；启动测试只应阻止目标目录中的游戏进程，不能因为其他目录的实例正在运行而误判。
- 任何启动诊断都必须在异常和中止路径中恢复文件，并以哈希复核恢复结果。
