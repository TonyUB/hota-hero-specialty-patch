# HOTA_NEW_HERO_V1.04_LOG_TEST1：逐队显示治愈值

状态：**双 EXE 静态门禁、可复现构建及临时副本启动冒烟均已通过；战斗内单体/群体日志仍待用户实机验收，尚未提升为正式 V1.04。**

## 目标

- 魔法书显示值保持 V1.03 原样。
- 单体治愈按“原版治愈施放提示 → 目标兵种治愈值 → 原版复活提示”的顺序写入战斗日志。
- 群体治愈按“原版治愈施放提示 → 所有有效受疗单位的治愈值 → 原版复活提示”的顺序写入战斗日志。
- 转世重生/复活提示继续使用原版语言资源、数量、资格与先后规则。

## 实现

1. 在尤兰德/阿斯特拉专属治愈包装器内部，将活体 `CureCore` 调用和全灭尸体计算调用分别改接到两个同调用约定的日志包装器；非治愈特长英雄仍直接走原版路径。
2. 单体目标在治愈结算完成后，读取 V1.03 F6 Direct 的最终总量，并通过原生日志追加函数立即写入一条 `%s: +%d`。`%s` 来自当前语言的兵种单数名称表，不新增中英文分支。
3. 群体目标在原有群体作用域内缓存兵种 ID 与最终治愈值，最多 14 队。原版治愈施放提示追加后，先逐队写出缓存的治愈值，再进入 TEST13/V1 已验收的原版复活提示回放。
4. 既有复活捕获函数主体与复活回放函数在入口之后的全部字节保持不变；本版仅在群体初始化中增加治愈值计数清零，并在复活回放入口前增加治愈值刷新跳板。

## 保持不变

- V1.03 F6 Direct 公式、目标等级取值与水系加成。
- 魔法书格式化路径及其调用上下文。
- `HotA.dat`，包括阿斯特拉的初级智慧术 + 初级水系魔法。
- 中英文 HeroSpec 档案与英雄特长描述。
- 永久复活资格、亡灵限制、尸体占格/重叠规则、动画、音效、起身动作以及原版复活提示文案。

## 验证

- `h3hota.exe` 与 `h3hota HD.exe` 均验证来源 V1.03 完整 SHA-256、所有 Hook 上下文字节、代码洞零态、RWX 映射、相对跳转目标与完整回滚。
- 两次相互独立构建生成完全相同的 ZIP。
- ZIP 通过 CRC、成员列表和逐文件 SHA-256 校验；除两个 EXE 与安装说明外，包内文件逐字节保持 V1.03。
- 在工作区内复制 `C:\Game\180\180` 形成独立临时游戏目录并覆盖测试包后，`h3hota HD.exe` 隐藏启动 12 秒仍存活，窗口标题为 `Heroes of Might and Magic III: Horn of the Abyss`，窗口句柄有效且进程处于响应状态；随后仅终止临时副本进程，未覆盖原游戏目录。

## 尚待实机确认

- 单体活体、单体全灭尸体各至少一次。
- 高级水系群体治愈同时包含活体受伤队、可复活尸体和无效/不可选目标。
- 日志中每个有效目标仅出现一条正确数值，顺序为治愈提示、全部治愈值、全部原版复活提示。
- 战斗结算、永久兵力、动画与音效无回归。

## 经验与风险

- 魔法书没有目标兵种上下文，不能直接代表按目标等级计算后的实际专属治愈量；本版只在结算路径记录最终值。
- 群体治愈的原版施法提示在所有目标结算之后才写入，不能在每队结算时直接追加日志，否则治愈值会再次排到施法提示之前。因此必须沿用已经实机证明有效的“延迟复活提示”时序，并把治愈值缓存插在两者之间。
- 静态回滚与启动冒烟不能证明战斗结算路径无崩溃，正式 V1.04 必须等待上述战斗测试通过。
