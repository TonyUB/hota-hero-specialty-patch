性质：诊断包，不是正式版本，不发布到 `Download/`

## 依据与目的

UIDIAG02 的 50 条实机记录中没有治愈术 ID 37，因此正式排除通用效果函数 `0x004E59D0`。本轮不再记录法术计算，而是挂接 EXE 内的 `sprintf` 类格式化函数 `0x006179DE`，只接受调用者位于 `0x00590000–0x005AFFFF` 的 UI 调用。

静态分析已经确认魔法书使用：

- `0x0059D119` → 格式串 `0x00684C3C`：`{%s}\n%s/%s\n%s: %d`；
- `0x0059D1E1` → 格式串 `0x00684C2C`：`{%s}\n%s\n%s: %d`。

诊断目标是同时捕获魔法书与战场底部提示的实际格式指针和数值参数，找出普通单位 `15`、大天使 `17` 和尸体无数值三条分支。

## 实现

- 从正式 `HOTA_NEW_HERO_V1.05` 重新构建；
- 继续使用新增 `.uidiag` 节，不使用任何既有零区；
- Hook：`0x006179DE` 的六字节序言 `55 8B EC 83 EC 20`；
- 跳板：重放序言后返回 `0x006179E4`；
- 记录器/过滤器/跳板/数据分别位于 `0x006E7000 / 0x006E7200 / 0x006E7300 / 0x006E7400`；
- 过滤器只检查调用者地址，不修改参数；记录完成后尾跳原生跳板；
- 最多写入 2048 条，避免异常 UI 循环导致文件无限增长。

每条记录为 64 字节（16 个小端 DWORD）：

1. `FMT1` 魔数；
2. 格式化调用者返回地址；
3. 目标缓冲区指针；
4. 格式串指针；
5. 前六个可变参数；
6. 格式串开头最多 16 字节（遇 NUL 停止）；
7. 两个保留 DWORD。

## 实机回收结果

- 回收文件：`hota_cure_uidiag03.bin`；
- SHA-256：`3bfbcef3e1ae53fce294e36a2beee8fe84c8c7bbb09f6e965d3bb46f9610a6c0f`；
- 文件大小：1088 字节；完整记录：17 条；
- 魔法书调用 `0x0059D128` 的第五个参数为 `5`，对应治愈术的法力消耗，不是治疗点数；
- 活体悬停由 `0x005A8BBC` 生成基础文本“施放%s在%s身上”；
- 尸体悬停由 `0x005A8BEC` 生成基础文本“施放%s”；
- 全部 17 条主程序记录中均未出现可见的 `15` 或 `17` 治疗点数。

由此确认：括号内的“治疗点数：15/17”是在基础提示之后由 `HotA.dll`（或其相邻 HotA 显示链路）追加，不能继续修改主程序 `sprintf`。静态反汇编同时找到 `HotA.dll!0x1002CCD0` 的治愈特长旧公式分支：对法术 ID 37 执行 `8 - 目标兵种等级`，而实机中 1 级英雄对普通单位显示 15、对 7 级大天使显示 17，恰好与旧版每级 10% 加成吻合。因此下一轮改为直接诊断 `HotA.dll` 的治疗文本格式化入口。
