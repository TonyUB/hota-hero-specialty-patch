# HOTA_NEW_HERO_V1.2_FIRSTATTACK_TEST2

- 类型：首次主动攻击必定幸运功能测试，不是正式发布版。
- 来源：正式 `HOTA_NEW_HERO_V1.11.zip`。
- 目的：修复 TEST1 日志显示写入成功、但所有攻击类型均未实际触发幸运的问题。

## TEST1 失败定位

- 用户回传 `hota_luck_firsttest01.bin`：1,728 字节，SHA-256 `b82209cd62ab9fa9bf70aaa8d40f278e398f4e87a03934d861f69738637b1522`，共 18 条完整记录。
- 逐队首次资格、主动攻击入口、英雄阵营门禁、攻守方指针匹配均正确。
- TEST1 的攻击回调确实记录到 `isLucky: 0 -> 1`，但写入位置早于 HotA 的真实幸运掷骰函数，随后被后者覆盖，因此动画和伤害均未生效。

## TEST2 修改

1. 保留已经由日志验证的行动 6/7 入口、42 位逐队资格表、战斗初始化清零和原生硬封锁后门禁。
2. 不再修改 `0x101392F0`、`0x10129560` 两个物理攻击回调。
3. 新钩子位于 HotA.dll 首选基址 `0x10133880`，即 HotA 实际幸运判定函数入口。
4. 符合首次主动攻击条件时，直接写入原生 `stack+0x70=1`，随后从 `0x101338E4` 继续执行 HotA 原生的幸运动画、音效、战斗日志与伤害流程。
5. 不符合条件（敌军、反击、后续主动攻击）时，从 `0x10133886` 回到完整原生幸运计算。
6. 诊断文件改为 `hota_luck_firsttest02.bin`：行动入口使用路径 30；真实幸运函数的强制分支使用路径 40；原生分支使用路径 41。

- 用户反馈当前测试项目均已实现，同意据此发布正式小版本。
