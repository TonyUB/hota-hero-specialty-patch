# “颂歌”专属魔法方案讨论记录

状态：**仅保存研究方案，V1.05 不实现，不进入当前补丁运行字节。**

## 目标英雄与载体

- 目标为壁垒幸运特长英雄梅洛迪娅与塔楼幸运特长英雄 Daremyth；后者的中文显示名以后续直接读取 HotA 1.8.0 本地化资源为准。
- 两人的英雄特长仍然是原版“幸运之神”，不新增全局英雄特长类型。
- “颂歌”使用原版“幸运之神”作为底层载体，在魔法书显示、施法入口和效果结算处按当前英雄身份做专属分流。
- 其他任何英雄看到、获得、学习和施放的都必须仍是原版“幸运之神”。

## 预期效果

1. “颂歌”只出现在两名指定英雄的魔法书中，魔法消耗为 0。
2. 施放后依次作用于己方全部有效兵队；每队先播放原版“幸运之神”演出，再播放原版“欢欣鼓舞”演出。
3. 结算结果不是在当前数值上叠加，而是把每队的有效幸运与士气直接设为 `+3 / +3`；因此负幸运、负士气或已有正值都统一归一到最大常规值。
4. 不创建额外“颂歌状态”图标。实际状态继续复用幸运之神与欢欣鼓舞的原生状态槽、覆盖关系和驱散路径。
5. 持续时间采用整场战斗有效的原生持续语义，直到被覆盖、被驱散或战斗结束；未来实现时必须先确认 HotA 1.8.0 的实际持续字段/哨兵值，不能仅凭静态常量推断。

## 专属性与鹰眼术隔离

- “颂歌”不是可被地图、魔法行会、学者、卷轴或鹰眼术识别的新全局法术 ID。
- 鹰眼术仍只记录和学习底层法术“幸运之神”。即使观察到两名指定英雄施放“颂歌”，其他英雄也不能因此获得“颂歌”。
- 非指定英雄若通过鹰眼术学会该法术，魔法书中显示并施放的仍是原版幸运之神，使用原版消耗、目标与效果。
- 未来 Hook 必须同时校验当前施法英雄身份与底层法术 ID；不得只修改全局幸运之神数据、名称、图标或效果。

## 自定义图标结论

可以使用自定义图标，但不能直接替换幸运之神的全局图标，否则其他英雄也会受到影响。推荐在两名指定英雄打开魔法书并绘制该槽位时，按英雄身份把图标、名称、说明和消耗临时替换为“颂歌”；其他上下文继续绘制原版幸运之神。自定义图标资源需要后续单独提供或制作，并同时验证标准版、HD 版、不同分辨率和中英文资源覆盖顺序。

## 推荐的未来实现层次

1. **显示层：** 英雄专属魔法书名称、说明、图标和 0 消耗。
2. **施法层：** 仅两名英雄把幸运之神施法入口分流到“颂歌”；其他英雄尾调用原版路径。
3. **目标层：** 枚举己方全部可受影响兵队，沿用原生免疫、存活和阵营检查。
4. **演出层：** 对每队依次调用原版幸运之神与欢欣鼓舞的动画/音效路径。
5. **状态层：** 使用两项原生状态，把有效幸运/士气稳定为 `+3 / +3`，采用整场战斗持续语义并保留原生驱散/覆盖行为。
6. **隔离层：** 鹰眼术、AI、地图学习、卷轴、魔法行会和非指定英雄始终只认识原版幸运之神。

## 实现前仍需诊断的项目

- HotA 1.8.0 中梅洛迪娅、Daremyth 的实际运行时英雄 ID 与中文显示名，以及幸运之神在魔法书、施法和鹰眼术记录处的真实入口。
- 原版幸运之神/欢欣鼓舞状态记录的数值字段、持续字段、覆盖规则和驱散规则。
- 负幸运/负士气、诅咒地形、禁魔环境、免疫士气单位、亡灵和构装体的交互边界。
- 群体逐队双演出的时序、日志文字、AI 估值及联机一致性。
- 自定义图标在标准版/HD 版和不同语言资源中的装载方案。

## 发布边界

本记录只用于保存已经确认的设计意图。任何未来测试包都必须先做只读诊断，证明上述运行入口，再分阶段实现显示层、施法层和状态层；不得在治愈数值版本中顺带修改幸运之神的全局行为。
