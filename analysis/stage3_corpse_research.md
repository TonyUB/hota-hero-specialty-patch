# Stage 3：治愈复活全灭尸体

状态：**静态路径已确认，`Patch_v2.5_STAGE3_TEST` 已构建；等待实机门禁。**

## 根因

治愈的法术 ID 为 `0x25`。原版目标解析函数 `0x005A3C60` 对治愈固定调用战场格的活体解析 `0x004E7230`；只有 `0x26` 和部分 `0x28` 复活法术会进入 `GetResurrectionTarget` `0x005A3FD0`。所以 Stage 2 能复活“仍有单位存活”的兵队，却无法让光标选择全灭尸体。

原版并未丢失尸体信息。每个战场格保留尸体所属阵营、原兵队槽位和重叠状态；`0x005A3FD0` 会据此还原原兵队指针，并调用 `0x005A83A0` 按原生转世重生规则检查阵营、亡灵/元素/构装等资格、占格冲突和复活上限。

## 单体目标路径

在 `0x005A3C77` 接入目标解析门：

1. 治愈仍先执行原活体解析，活体目标行为完全不变。
2. 只有英雄施法、目标阵营等于当前施法方、当前英雄为尤兰德 `0x19` 或阿斯特拉 `0xAA`，且活体解析为空时，才调用 `GetResurrectionTarget(side, hex, context=0)`。
3. `0x005A3D26` 只对已经由上述原生复活解析确认、并且 `numberAlive == 0` 的治愈目标直接判定可选，避免再次调用只适用于活体的 Cure 效果校验。
4. 非特长英雄、战斗生物施法和普通活体治愈继续走原版分支。

## 全灭兵队结算

全灭兵队不能调用 `CureCore`：该函数会访问活体生命损失、状态清除和当前单位数相关字段，但不会把 `numberAlive` 从零恢复。

测试版按 CureCore 的原生公式计算完整治愈量：

```text
amount = CureBase[waterMastery] + CurePowerCoefficient * spellPower
amount += hero->NativeSpellSpecialtyBonus(Cure, targetLevel, amount)
```

随后再次要求 `GetResurrectionTarget` 返回的指针与当前尸体兵队完全一致，再调用：

```text
ResurrectTarget(target, amount, temporary=0)
```

不直接写 `numberAlive`、`healthLost`、`numberForeverDead` 或其他兵队状态字段。

## 高级水系群体路径

原群体治愈在 `0x005A1B30–0x005A1BEC` 遍历当前阵营兵队槽位并处理活体。测试版在该循环结束后的 `0x005A1BEC` 接入第二次扫描：

- 仍使用 `[manager + side*4 + 0x54BC]` 的当前阵营槽位数；
- 每个战斗兵队结构大小为 `0x548`，阵营每侧预留 21 个槽位；
- 只考虑 `numberAlive == 0` 且初始单位数大于零的记录；
- 使用尸体自身的战场格再次调用 `GetResurrectionTarget`，并要求返回指针完全一致；
- 每个合格尸体使用完整治愈量永久复活；
- 已复活槽位加入原群体治愈的受影响标记数组，随后继续执行原版群体动画/日志路径。

活体兵队先按 Stage 2 完成正常治疗和溢出复活；尸体扫描发生在其后。多个尸体或活体占用同一落位时，以原生尸体解析和占格规则为准。

## 实机门禁

在以下项目全部由用户确认前，不得把测试版提升为正式补丁：

1. 尤兰德、阿斯特拉都能用单体治愈选中并复活合法的全灭尸体。
2. 两名英雄的高级水系群体治愈都能同时处理活体和多个合法尸体。
3. 全灭亡灵不能被单体选择，也不会被群体治愈复活。
4. 非特长英雄不会获得尸体目标或群体尸体扫描。
5. 复活数量符合完整治愈量换算，动画和战斗日志不破坏流程。
6. 新增单位在战斗结束后永久保留。
