状态：**TEST4 功能、动画与音效门禁全部通过；`Patch_v2.6_VISUAL_TEST12` 正在验证最后的群体日志顺序。**

## 目标

- 治愈术自身动画；

## 原生函数边界

`ResurrectTarget` 位于 `0x005A7870`。静态反汇编显示：

1. `0x005A7870–0x005A7991`：生命、数量上限、永久死亡字段、尸体还原、落位及朝向等状态处理。
2. `0x005A79A1–0x005A7A43`：计算复活数量并写入“起死回生”战斗记录。
3. `0x005A7A44–0x005A7B6C`：加载资源、设置单位动画状态并等待复活动画演出。
4. `0x005A7B6D–0x005A7B9C`：公共收尾与返回。

原版的自动结算/无动画路径在 `0x005A799B` 直接跳到 `0x005A7B6D`，因此无需复制复活数值代码，可以复用原生函数并在动画入口做条件跳过。

## TEST2 崩溃定位

实机在复活尸体时报告：

- 异常：读取 `0x00000028`；
- 地址：`HotA.dll+0x64AFF`；
- 寄存器：`ECX=0`；
- 调用来源：`HotA.dll+0x720CA`。

干净 HotA 1.8.0 的对应指令为：

```asm
10064AF0  mov edx, dword ptr [0x699420]
10064AF9  mov ecx, dword ptr [edx + 0x132e8]
10064AFF  cmp dword ptr [ecx + 0x28], 0
```

`[battle + 0x132e8]` 正是 TEST2 通过效果 ID `-1` 清空的复活圆圈对象。原版 EXE 在读取该对象前会检查空指针，HotA 的额外绘制函数却没有同样的检查；兵种起身循环调用战场刷新时因而崩溃。结论是：不能通过删除/清空对象来隐藏圆圈。

## 受击姿势根因

`0x005A7B22–0x005A7B6B` 的原生循环在动画组 5 中倒放死亡帧。假设死亡动画有 `N` 帧：

1. 前 `N` 次循环把帧号从 `N-1` 依次写到 `0`；
2. 只有第 `N+1` 次循环满足 `EDI >= [EBP+0x10]`，才会进入 `0x005A7B3D`；
3. 原版分支随后把 `[ESI+0x3C]` 从动画组 5 改为站立组 2，并把 `[ESI+0x40]` 帧号清零。

TEST3 将总循环数设为恰好 `N`，用于去掉不可见复活圆圈带来的额外等待，但因此没有执行第 `N+1` 次原生状态切换。死亡动画第 0 帧在视觉上就是受击姿势。

## TEST4 修正

- 治愈专用总循环数从 `N` 调整为 `N+1`。
- 不手工写动画组或动画帧；新增的一次循环让原版 `0x005A7B3D–0x005A7B44` 自行回到站立组 2、帧 0。
- 为容纳单字节 `INC EAX`，作用域标记从已验证低代码洞末字节 `0x00639D3F` 移到已验证高代码洞末字节 `0x00639D7F`。
- 其余 TEST3 逻辑不变：保留合法圆圈对象但写入越界公开帧，跳过复活音效，保留治愈术演出/音效与公共标记清理。

## TEST5 群体崩溃
