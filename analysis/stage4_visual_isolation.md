# Stage 4：仅保留治愈动画

状态：**TEST1 群体显示失败；TEST2 实机崩溃；`Patch_v2.6_VISUAL_TEST3` 已构建，等待重测。**

## 目标

只对尤兰德、阿斯特拉由治愈触发的复活隐藏转世重生动画。保留：

- 治愈术自身动画；
- 原生复活数值与资格限制；
- 尸体还原、落位与占格限制；
- `temporary=0` 的战后永久性；
- 原生“起死回生”战斗记录；
- 普通转世重生法术的原版动画。

## 原生函数边界

`ResurrectTarget` 位于 `0x005A7870`。静态反汇编显示：

1. `0x005A7870–0x005A7991`：生命、数量上限、永久死亡字段、尸体还原、落位及朝向等状态处理。
2. `0x005A79A1–0x005A7A43`：计算复活数量并写入“起死回生”战斗记录。
3. `0x005A7A44–0x005A7B6C`：加载资源、设置单位动画状态并等待复活动画演出。
4. `0x005A7B6D–0x005A7B9C`：公共收尾与返回。

原版的自动结算/无动画路径在 `0x005A799B` 直接跳到 `0x005A7B6D`，因此无需复制复活数值代码，可以复用原生函数并在动画入口做条件跳过。

## TEST1 实现

- v2.5 的三个治愈专用 `ResurrectTarget` 调用改走 `0x00639D30`，设置一次作用域标记后尾跳原生 `0x005A7870`。
- `0x005A7A44` 改为视觉门：标记为零时重放原指令并进入原版动画；标记为一时清零并跳到 `0x005A7B6D`。
- `0x005A799B` 的原版自动结算跳转改到 `0x00639D20`，先清除标记，再等价跳到原目标，避免无动画模式留下标记。
- 没有手工写 `numberAlive`、`healthLost` 或 `numberForeverDead`。

## 静态验证结果

- 从唯一可信的 `Patch_v1.8` 重新构建，并非在 v2.5 EXE 上叠加修改。
- 修改 `build_stage3_patch.py` 的默认参数后重建 TEST3，ZIP SHA-256 仍为 `11d3d34175b8b15b5de7f8c5af31e9809762cdb76909910704936e2b43fd8c73`，证明 v2.5 构建路径未漂移。
- 标准版和 HD 版相对 v2.5 都只有 66 个差异字节、13 个精确区间，差异集合完全一致。
- 两个 EXE 大小不变，完整回滚均重建 Patch_v1.8 输入；非 EXE 文件逐项不变。
- 测试 ZIP 连续重建两次哈希一致：`82aaeb8983bf585a1a9f5042157f301e8961d79592113023c2f1132f1eb48cc2`。
- 静态检查不能证明最终动画组合，必须由实机确认后才能生成正式 v2.6。

## 实机门禁

1. 两名英雄单体治愈复活存活兵队：只显示治愈动画，数量不变。
2. 两名英雄单体治愈复活全灭尸体：只显示治愈动画，数量不变。
3. 高级水系群体治愈复活多队：不逐队显示转世重生动画，治愈动画仍存在。
4. 普通转世重生：原版动画仍存在。
5. 复活单位战后永久保留；亡灵、重叠尸体与占格规则不变。

## TEST1 实机反馈

- 单体治愈复活没有问题。
- 高级水系群体治愈同时复活多队尸体时，复活数值和战斗记录已经生效，但战场贴图仍停留为地面尸体；鼠标移动到对应位置后才显示部队。

结论：TEST1 从 `0x005A7A44` 跳到公共收尾时，不仅删除了灰棕色圆圈，也跳过了兵种起身帧和逐队刷新。

## TEST2 修正

TEST2 不再跳过整个视觉块：

1. 在 `0x005A7A50` 读取真实的复活效果 ID 并保存。
2. 仅对治愈触发的复活，临时把该 ID 改为 `-1`，让原生代码自行释放/清空圆圈对象。
3. 在 `0x005A7AF5` 恢复真实 ID 和原始栈，再继续原版音效、兵种起身帧、逐帧刷新与收尾。
4. 普通转世重生全程使用真实 ID，圆圈和起身动画均不改变。

TEST2 从 `Patch_v1.8` 重建；标准版与 HD 版相对 v2.5 均为 75 个差异字节、16 个精确区间，差异集合一致。ZIP 连续重建两次 SHA-256 均为 `3232c2e7dc815046e120d88c2c5ba3c84190ff326b220db6a231731a37a39713`。

## TEST2 崩溃定位

实机在复活尸体时报告：

- 异常：读取 `0x00000028`；
- 地址：`HotA.dll+0x64AFF`；
- 寄存器：`ECX=0`；
- 调用来源：`HotA.dll+0x720CA`。

干净 HotA 1.8.0 的对应指令为：

```asm
10064AF0  mov edx, dword ptr [0x699420]
10064AF9  mov ecx, dword ptr [edx + 0x132e8]
10064AFF  cmp dword ptr [ecx + 0x28], 0
```

`[battle + 0x132e8]` 正是 TEST2 通过效果 ID `-1` 清空的复活圆圈对象。原版 EXE 在读取该对象前会检查空指针，HotA 的额外绘制函数却没有同样的检查；兵种起身循环调用战场刷新时因而崩溃。结论是：不能通过删除/清空对象来隐藏圆圈。

## TEST3 修正

TEST3 保留真实效果 ID 和合法特效对象，仅改变治愈专用演出：

1. `0x005A7AF5`：普通转世重生重放原指令；治愈复活只取兵种自身起身帧数，设置起身状态并直接进入 `0x005A7B12`，从而跳过复活音效调用。
2. `0x005A7B22`：普通转世重生写入原版逐帧序号；治愈复活写入远大于动画帧数的正数栈帧地址，使 EXE 与 HotA 绘制器都判定圆圈帧越界而不绘制，同时对象保持合法。
3. `0x005A7B6D`：在公共收尾入口清除作用域标记并重放原指令；正常动画与原版自动结算/无动画跳转都会经过该入口。
4. 治愈术自身演出和音效发生在进入原生复活函数之前，未被修改；普通转世重生的圆圈、声音和起身动作也不变。

TEST3 从 `Patch_v1.8` 独立重建两次，ZIP SHA-256 均为 `f2e9a0f159c86d7f9e35a83731e10ea7e07566e963fb31c7610910f44eca2353`。标准版与 HD 版相对正式 v2.5 均为 91 个差异字节、19 个精确区间，差异集合完全一致；两个 EXE 的原字节、Hook 目标、PE 尺寸、`MainProc`、完整回滚、非 EXE 文件哈希和 ZIP CRC 均通过静态检查。
